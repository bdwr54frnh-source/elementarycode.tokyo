Elementary Code

Elementary Code is a new authentication code generated within the dedicated application.

The code is embedded in a transmission icon. By checking the icon with a compatible application and device, the connection with the other party can be authenticated.

One of its key features is that communication can be initiated through a dedicated transmission icon without directly sharing a conventional telephone number.

How it works

  1. Generate a transmission icon within the dedicated application.
  2. The Elementary Code is embedded in the icon.
  3. The recipient checks and authenticates the code using the compatible application.
  4. Once authentication is completed, communication can begin.

Elementary Code is not simply a displayed number or character string. It is designed to authenticate the relationship between the transmission icon and the other party by combining the dedicated application with a compatible device.

Authentication is designed to be completed in a short period of time.

For security and technical reasons, the specific generation, verification algorithms, and internal technical specifications are not publicly disclosed.

What "uniqueness" means

In practice, this idea of uniqueness means that no two Elementary Codes are ever the same, and no code is issued twice. Even if two people checked at the exact same moment, they would not be looking at the same code. It is less like a printed serial number and more like a single key that only ever exists once, in one place, at one time.

エレメンタリーコード

エレメンタリーコードは、専用アプリの中で生成される、新しい認証コードです。

発信アイコンに組み込まれたエレメンタリーコードを、対応するアプリと端末で確認することで、相手とのつながりを認証します。

通常の電話番号を直接伝えることなく、専用の発信アイコンを通してコミュニケーションを始められることが大きな特徴です。

かんたんな仕組み

  1. 専用アプリで発信アイコンを生成します。
  2. アイコンにエレメンタリーコードが組み込まれます。
  3. 相手側の対応アプリでコードを確認・認証します。
  4. 認証が完了すると、コミュニケーションを開始できます。

エレメンタリーコードは、単なる数字や文字列を表示するためのものではありません。専用アプリと対応する端末を組み合わせて確認することで、発信アイコンと相手との関係を認証するための仕組みです。

認証は短時間で行える設計になっています。

安全性と技術上の理由から、エレメンタリーコードを生成・検証する具体的なアルゴリズムや内部仕様の詳細は公開していません。

「一意性」とは何か

「一意性(uniqueness)」とは、簡単に言うと、まったく同じエレメンタリーコードが二つと存在せず、同じコードが二度発行されることもない、という意味です。仮に同じ瞬間に二人が確認したとしても、二人が見ているコードが同じものになることはありません。印刷されたシリアル番号というより、その瞬間・その場所にしか存在しない一本の鍵のようなものだとイメージすると分かりやすいと思います。

Why Elementary Code Is Different

Elementary Code was developed from a simple question:

Why did a system like this not already exist?

Before submitting the patent application, existing technologies and patents were investigated. If the same invention had already been patented, there would have been no reason to submit an application for the same idea.

The developer also considered another question:

If I tried to reproduce this system myself, could I simply copy it?

The concept was designed so that it cannot simply be reproduced from what is visible.

If someone does not know where the actual code exists at a particular moment, or how it is connected to the corresponding system and device, copying what is visible would not reproduce the system itself.

This difficulty in copying and reproducing the system is one of the fundamental ideas behind Elementary Code.

A Future Application: Vehicle Security

The concept of Elementary Code is not limited to communication.

One planned future application is vehicle anti-theft technology.

Vehicle theft remains a serious issue, and high-value vehicles can become targets of theft.

The idea is to incorporate Elementary Code into a vehicle key and security system.

There is an important distinction between making theft absolutely impossible and making undamaged, unauthorized access extremely difficult.

If someone is willing to destroy a vehicle in order to steal it, no security system can reasonably guarantee that the physical object can never be taken.

The important question is:

Can a vehicle be opened quickly and without leaving any damage?

With a conventional key, copying the key can allow the copied key to be used for unlocking. The person operating the copied key does not necessarily need to be the original owner.

With an Elementary Code-based system, unlocking would also require the designated device.

The security concept is therefore based on a combination of:

Correct Elementary Code + Designated Device + Device Authentication

For compatible iOS devices, this could also be combined with device-level authentication such as facial recognition.

This means that simply copying a conventional key would not be sufficient to operate the system.

The future objective is therefore to make undamaged, short-time theft extremely difficult.

This vehicle-security application is planned as a future development following the Google version of the system. It should be presented as a development concept, not as a currently proven vehicle-security product.

なぜエレメンタリーコードは違うのか

エレメンタリーコードは、ひとつのシンプルな問いから生まれました。

なぜ、このような仕組みがこれまで存在しなかったのか。

特許出願の前に、既存の技術や特許を調査しました。もし同じ発明がすでに特許化されていたなら、同じアイデアで出願する理由はありませんでした。

開発者はもうひとつの問いも考えました。

自分でこの仕組みを再現しようとしたとき、単純にコピーできてしまうだろうか。

この仕組みは、目に見える部分だけからは簡単に再現できないように設計されています。

ある瞬間に実際のコードがどこに存在し、対応するシステムや端末とどのように結びついているかが分からなければ、見えているものをコピーしても、仕組みそのものを再現することにはなりません。

このコピー・再現のしづらさが、エレメンタリーコードの根底にある考え方のひとつです。

将来的な応用構想:車両セキュリティ

エレメンタリーコードの考え方は、通信だけに限定されません。

将来的な応用のひとつとして、車両の盗難防止技術を構想しています。

車両の盗難は依然として深刻な問題であり、高額な車両は盗難の対象になりやすいという現状があります。

エレメンタリーコードを車両のキーおよびセキュリティシステムに組み込むという発想です。

「盗難を絶対に不可能にすること」と「傷をつけずに不正アクセスすることを極めて困難にすること」には、重要な違いがあります。

もし盗む側が車両を破壊する覚悟であれば、どんなセキュリティシステムでも、物理的に持ち去られないことを合理的に保証することはできません。

重要な問いは次の点です。

車両を、傷をつけずに短時間で開けることができるかどうか。

従来型の鍵の場合、鍵を複製すれば、その複製された鍵で解錠できてしまいます。複製された鍵を操作する人が、必ずしも本来の所有者であるとは限りません。

エレメンタリーコードをベースにしたシステムでは、解錠には指定された端末も必要になります。

このセキュリティの考え方は、次の組み合わせに基づいています。

正しいエレメンタリーコード + 指定された端末 + 端末側の認証

対応するiOS端末であれば、顔認証のような端末レベルの認証と組み合わせることも考えられます。

つまり、従来の鍵を複製しただけでは、このシステムを操作するには不十分ということになります。

将来的な目標は、傷をつけずに短時間で行われる盗難を極めて困難にすることです。

この車両セキュリティへの応用は、Googleバージョンのシステムに続く将来的な開発として構想されているものであり、現時点で実証済みの車両セキュリティ製品として提示するものではありません。

Light-Guided Interface (発光誘導型精製インターフェース)

This is a separate concept from Elementary Code, developed independently.

Rather than using light purely as decoration, this concept treats light itself as an interface — a way of visually communicating status, direction, and next actions to the user.

AIR DEFLECT

AIR DEFLECT is an independent and important part of this interface concept, particularly in relation to the shutter's opening.

When a shutter opens, the opening itself is treated as part of the interface. The opening, combined with light and on-screen indicators, is used to communicate the user's current state and direction — the light is not an incidental visual effect.

The specific patent claims and internal technical details of this interface are not disclosed here.

Elementary Code — A Way to Check for Yourself

For example, suppose someone who says they are "a friend of a friend" sends you an icon containing a photo of a soccer player.

In this case, judging whether the person in the photo is genuinely who they claim to be — based on the image or design alone — is not something Elementary Code can determine.

However, if what you want to confirm is whether the icon itself is genuine or a copy, actually connecting through it is the fastest way to check.

If an icon contains only a serial number, that number is simply a manufacturing number — it cannot, by itself, be used to place a call.

On the other hand, an icon with a correctly embedded Elementary Code will, through that code, connect properly to the party associated with that design.

Another important point is who the icon was actually sent by.

Elementary Code is not a system where simply copying an image or design lets someone else freely use it as their own. Because the code corresponds to the original sender, circumstances such as buying it from a friend, winning it at auction, or copying only the photo do not, by themselves, allow someone other than the original sender to use it freely.

In other words, rather than judging whether the person in a photo is genuine from the image alone, the idea is to confirm whether an icon carries a legitimate Elementary Code by actually connecting through it.

Elementary Code ― 自分でもできる見分け方

例えば、「友達の友達」だという人から、サッカー選手の写真が入ったアイコンが送られてきたとします。

この場合、「この写真の人物が本人かどうか」という、写真そのもののデザインを見て判定することは、Elementary Codeだけでは行えません。

しかし、「このアイコン自体が本物なのか、それともコピーされたものなのか」を確認したい場合は、実際に接続してみることが、いちばん早い確認方法になります。

アイコンにシリアル番号だけが入っている場合、その番号は製造番号にすぎず、その番号だけで電話をかけることはできません。

一方、正しいElementary Codeが組み込まれたアイコンであれば、そのコードを通じて、そのデザインに対応する相手へときちんとつながります。

そしてもうひとつ重要なのは、「誰から送られてきたアイコンなのか」という点です。

Elementary Codeは、画像やデザインを単純にコピーしただけで、別の人が自分のものとして自由に使えてしまう仕組みではありません。送信者との対応関係があるため、友達から買った、オークションで落札した、写真だけをコピーした、といった経緯だけでは、元の送信者とは別の人が自由に使用できるわけではありません。

つまり、写真に写っている人物が本人かどうかを画像だけで判定するのではなく、実際に接続してみることで、そのアイコンが正規のElementary Codeを持つものかどうかを確認する、という考え方です。

Silent Design

The device is built with a silent design — no sound is played through a speaker.

Sound is only ever heard through connected headphones, or through the earpiece during a call, just like a regular phone call.

静音設計

本製品はスピーカーから音を出さない、静音設計になっています。

音が聞こえるのは、ヘッドフォンを接続した時、または通話中の受話口(耳から聞こえる音)のみです。
