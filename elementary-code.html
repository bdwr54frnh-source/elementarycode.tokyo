エレメンタリーコード

エレメンタリーコードは、専用アプリの中で生成される新しい認証コードです。

発信アイコンに組み込まれたコードを、対応するアプリと端末で確認することで、相手とのつながりを認証します。

通常の電話番号を直接伝えることなく、専用の発信アイコンを通してコミュニケーションを始められることが大きな特徴です。

かんたんな仕組み

  1. 専用アプリで発信アイコンを生成します。
  2. アイコンにエレメンタリーコードが組み込まれます。
  3. 相手側の対応アプリでコードを確認・認証します。
  4. 認証が完了すると、コミュニケーションを開始できます。

「一意性」とは何か

まったく同じエレメンタリーコードが二つと存在せず、同じコードが二度発行されない、という考え方です。仮に同じ瞬間に二人が確認しても、同じコードを見ている状態にはなりません。

なぜエレメンタリーコードは違うのか

見えている数字や文字列だけをコピーしても、コードが存在する場所、対応する端末、認証の関係まで再現できなければ、仕組みそのものを複製したことにはなりません。

安全性と技術情報

安全性と技術上の理由から、具体的な生成・検証アルゴリズムや内部仕様の詳細は公開していません。

高速転送・一致照合の測定結果（2026年10月10日）

12桁の数字列10万件について、同一プロセス内のメモリ上でコードを配列間に転送し、元の値との完全一致を確認するマイクロベンチマークを実施しました。これはエレメンタリーコードの構想に関連する基礎処理の参考測定であり、実製品の認証速度を測ったものではありません。

  • 測定件数：100,000件（12桁）
  • 今回の総処理時間：18.962ミリ秒
  • 1件当たり平均：0.18962マイクロ秒（約189.62ナノ秒）
  • 転送後の一致確認：100,000件すべて成功
  • 今回生成した入力同士の完全重複：0件
  • 前回報告した参考値：18.113ミリ秒、平均0.181マイクロ秒

この結果で確認できたこと

今回のPython試験では、事前に生成したコードの参照をメモリ内で代入し、等値比較する処理が短時間で終了しました。生成時間は測定対象に含みません。10万件の一致成功は転送後のデータの一致を示し、重複0件は今回抽出した入力の範囲での観測結果です。

試験の範囲と注意点

実施環境はMacではなくLinuxのPython実行環境です。通信遅延、時刻同期、暗号処理、コードの生成・配信、端末間照合、ユーザーインターフェース、実際の認証全体は含まれていません。また、今回の代入は文字列データの物理的なコピー速度ではなく、Python上の参照の代入と比較を主として測定しています。実運用上の世界最速認証や、コードが将来にわたって絶対に重複しない数学的な一意性、第三者への安全性を、この試験だけで証明したものではありません。

将来的な応用構想

エレメンタリーコードの考え方は通信だけに限定せず、将来的には車両セキュリティなどへの応用も構想しています。現時点では将来構想であり、完成済みの車両防犯製品を示すものではありません。

Elementary Code

Elementary Code is a new authentication code generated inside the dedicated application.

The code is embedded in a transmission icon. A compatible app and device can check the code and authenticate the connection with the other party.

A key feature is that communication can begin through the dedicated icon without directly sharing a conventional telephone number.

How it works

  1. Generate a transmission icon in the dedicated application.
  2. The Elementary Code is embedded in the icon.
  3. The recipient checks and authenticates the code with a compatible application.
  4. After authentication, communication can begin.

What uniqueness means

The concept is designed so that the same Elementary Code is not issued twice. Even if two people check at the same moment, they are not intended to be looking at the same code.

Why it is different

Copying only the visible numbers or characters does not reproduce the full system unless the code location, designated device, and authentication relationship are also reproduced.

Security and technical details

For security and technical reasons, detailed generation and verification algorithms and internal specifications are not publicly disclosed.

Transfer and equality-check benchmark (10 October 2026)

A local Python microbenchmark processed 100,000 pre-generated 12-digit strings, assigning each string to another array position and checking exact equality in the same process. This is a reference test for a basic operation relevant to the Elementary Code concept, not a measurement of end-to-end product authentication.

  • Inputs: 100,000 strings of 12 digits
  • Elapsed time in this run: 18.962 milliseconds
  • Average: 0.18962 microseconds per assignment and check (about 189.62 nanoseconds)
  • Successful equality checks: 100,000 of 100,000
  • Exact duplicate inputs observed: 0
  • Earlier reported reference figures: 18.113 milliseconds, 0.181 microseconds average

What was demonstrated

Assignment of pre-generated Python string references and equality checking completed quickly in memory. Input generation time was excluded. Zero observed duplicates applies only to the generated sample.

Scope and limitations

The test was run in a Linux Python environment, not on a Mac. It excluded communication, synchronization, cryptography, code issuance, cross-device validation, user interface, and full authentication. Python reference assignment does not measure copying the underlying string bytes. These measurements do not establish world-record authentication speed, cryptographic security, or a mathematical guarantee that every future code will be unique.

Future applications

The concept is not limited to communication. Future applications such as vehicle security are under consideration. These are development concepts, not claims about a currently completed vehicle-security product.
